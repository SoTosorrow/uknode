# uknode

本地节点与连线编辑器。支持节点和连线编辑、多父级收录、按范围浏览与独立布局，以及 SQLite 自动增量保存和会话撤销重做。基础节点以短 ID 显示，没有名称、笔记等业务字段；视频业务节点可以展示图片、提示词与配置。界面采用细线框节点、点阵画布和悬浮工具条，支持框选与右键菜单。

节点是稳定锚点、业务数据挂载点，也可以作为其他节点的结构容器。业务数据通过节点 ID 关联；节点之间通过 `base_memberships` 挂载。基础节点与挂载关系不预设业务意义，名称、内容、参数及行为由独立业务模块解释。当前“收录”弹窗是默认的结构浏览方式。定义及业务接入边界见 [`design.md` 第 2 节](design.md#2-核心概念与边界)。

节点、连线和保存批次统一使用 `nanoid(12)` 生成 12 位 ID（大小写字母、数字、`_` 和 `-`）。节点和连线生成时避开已加载及本次会话用过的 ID。界面直接完整显示 ID，接口只接受这一种格式；SQLite 使用 TEXT 字段存储。

## 运行

需要 Node.js 24。在项目根目录运行：

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。同一命令启动 Vite 和本地 Fastify 服务，前端的 `/api` 请求代理到服务端。

正式本地运行：

```sh
npm run build
npm start
```

打开 http://127.0.0.1:3000 。Fastify 通过官方插件 `@fastify/static` 提供构建后的 HTML、JavaScript 和 CSS，页面与 API 同源。服务仅监听本机，不把 SQLite 文件交给浏览器读取。

数据库默认位于 `data/uknode.sqlite`，首次启动自动创建目录和数据库并执行迁移。可用 `UKNODE_DATA_DIR` 指定其他目录，`PORT` 修改后端端口。数据库、依赖和构建产物不提交 Git。请始终从项目根目录运行命令。

## 数据库定义与同步

**基础表定义在 [`src/storage/schema.ts`](src/storage/schema.ts)，业务表定义在各自 `src/ext/<业务>/schema.ts`**。这些文件明确声明表名、字段、主键、外键、索引和检查约束：

| 定义 | SQLite 表 | 职责 |
| --- | --- | --- |
| `baseNodes` | `base_nodes` | 稳定锚点的 ID、创建与更新时间；没有业务字段 |
| `baseEdges` | `base_edges` | 连线 ID、两端节点 ID、方向及时间 |
| `baseMemberships` | `base_memberships` | 无预设业务意义的直接挂载；当前支持多父级，禁止循环 |
| `viewNodeLayouts` | `view_node_layouts` | 各范围的独立坐标；`context_node_id` 为空表示全局画布 |
| `baseStoreState` | `base_store_state` | 当前修订号 |
| `baseBatchReceipts` | `base_batch_receipts` | 最近 1,000 个批次的幂等回执；没有操作内容 |
| `videoNodes` | `ext_ai_video_nodes` | 视频业务节点类型、图片、提示词、输出参数与输入顺序；定义在 `src/ext/ai-video/schema.ts` |

`base_schema_migrations` 由 Drizzle 管理，用于记录已执行的迁移；名称在 `drizzle.config.ts` 和服务启动配置中一致指定。

修改表结构的流程：

1. 修改对应的基础或业务 `schema.ts`。
2. 运行 `npm run db:generate -- --name=变更名称`，由 Drizzle Kit 生成 `migrations/` 下的 SQL 与结构快照。
3. 查看生成的 SQL。变更已有数据前，先备份当前数据库。
4. 运行 `npm run db:migrate`，将迁移应用到 SQLite；启动服务也会应用尚未执行的迁移。
5. 将表定义和迁移文件一起提交。不要只改数据库而遗漏代码定义。

初始迁移为 `migrations/0000_initial.sql`；`0001_memberships_and_scoped_layouts.sql` 增加收录关系和范围布局，保留旧坐标为全局布局。布局表使用“范围＋节点”唯一索引，另用部分唯一索引确保空范围下的节点也只能有一条坐标。

`0002_remove_edge_description.sql` 删除旧连线说明列，保留连线 ID、端点、方向和时间；同时清空旧格式的批次回执，并将已有数据库修订号增加 1。升级前关闭旧页面，更新并重启服务后重新打开，避免沿用旧接口和待保存请求。

启动服务不会按运行时对象猜测字段，也不会清空重建数据库。修改 schema.ts 后必须先生成并审阅迁移，才能把结构变化应用到数据库。已有数据上的破坏性结构变更仍需单独确认。

## 操作与保存

- 点击底部“新增节点”，或右键画布空白处新增；右键新增使用鼠标所在的画布位置。
- 拖动节点调整坐标。悬停或选中节点时显示连接点，从右侧连接点拖到另一节点左侧连接点创建连线。
- 点击节点，在右下角查看现有 ID 和坐标；点击连线，在同一详情卡查看端点并编辑方向。详情卡可折叠，折叠状态只保留在本页会话。
- 左键拖动空白处框选完整包含的节点；Shift 点击节点可追加选择。选区支持整体移动、删除和撤销。多选详情显示选中数量。
- 右键节点打开“新增节点／删除节点”菜单。右键未选节点会切换为单选；右键已选节点会保留多选，删除这些节点及其关联连线。空白处菜单禁用删除。
- 选中节点或连线，点击“删除选中”；删除节点会同时删除关联连线和坐标。
- 使用“撤销”“重做”或 Ctrl/⌘ Z、Ctrl/⌘ Shift Z。输入框内仍使用浏览器原生文字撤销。
- 按住空格再拖动，或按住鼠标中键拖动来平移；使用滚轮或左下角控件缩放、适应画布。
- 右键菜单支持方向键选择和 Enter 执行；按 Escape、点击外部或移动视口关闭菜单。

## 收录弹窗

- 单击节点选中，双击节点或点击详情里的“查看收录节点”，打开可编辑画布弹窗。弹窗只显示母节点的直接成员和成员之间的普通连线；母节点显示在标题中，间接成员需要逐层打开。
- 在弹窗顶部选择已有节点并点击“收录”。同一节点可以被多个节点收录，也可以自己收录成员；直接或间接包含自身会被拒绝。
- 在弹窗内继续打开节点，复用同一个弹窗。顶部显示浏览路径，“返回”回到之前浏览的母节点。点击关闭或按 Esc 回到主画布，保留主画布的缩放、平移和仍然存在的选中对象。
- “解除收录”只删除当前母节点的直接收录关系，成员立即从当前弹窗移出；节点、其他母节点的收录、普通连线和保存的布局都保留。即使还有间接路径，也不会混入直接成员画布。
- 弹窗工具栏和右键菜单分别提供“解除收录”和“彻底删除”。在弹窗内按 Delete / Backspace，选中节点时解除收录，仅选中连线时删除连线。涉及共享关系的彻底删除会提示影响范围。
- 在弹窗中新建节点，会同时创建节点、直接收录关系和当前母节点下的坐标；引用已有节点不复制对象。空母节点也可以从弹窗顶部收录已有节点。
- 每个范围独立保存坐标。没有坐标时使用初始网格，浏览本身不写数据库；拖动结束才保存。解除收录保留布局，重新收录可恢复之前摆放的位置。
- 主画布的“删除选中”及“删除节点”仍是彻底删除，会清理所有相关收录、连线和范围布局；未选中的子成员保留。批量解除收录和彻底删除都可以一次撤销。
- 右键菜单内按 Esc 先关闭菜单，再次按 Esc 才关闭弹窗。弹窗关闭后保存队列继续工作；浏览路径仅保留在本次弹窗内，刷新回到主画布。

普通连线允许成环、自连接和同端点多条边。

编辑先更新前端内存，并按对象保留待保存的最终变更，包括删除。拖动结束提交坐标，相关修改以 300 毫秒防抖合成批次并按顺序发送。连续编辑同一业务字段在 1 秒内合并撤销记录。新建后立即删除可能提交一次无实际数据变化的删除，仍会推进修订号。后端在事务内检查修订号，依靠外键校验节点引用，再增量写入当前表。

发送中的批次固定 ID 和内容；期间的新修改进入下一批。响应丢失时重试相同批次，服务端先查幂等回执，避免重复执行。只在收到对应回执后显示已保存。失败时保留修改；修订冲突停止写入，不自动覆盖其他页面的数据。“重新读取”需要确认放弃本页尚未确认的修改。

前端最多保留当前会话 100 个撤销动作。没有永久历史或 IndexedDB 草稿恢复；异常关闭可能丢失尚未确认的修改。刷新会清空会话撤销记录。

## 代码位置与验证

| 目录 | 职责与主要文件 |
| --- | --- |
| `src/core/` | `model.ts` 定义锚点和关系；`changes.ts` 定义基础变更；`graph.ts` 应用变更、删除关联和校验结构；`traversal.ts` 查询成员、后代和检查循环。纯函数，不依赖画布、存储或运行协调层。 |
| `src/runtime/` | `document.ts` 组合图、持久布局及业务附加数据，`protocol.ts` 定义保存批次和 HTTP 校验，`errors.ts` 定义写入错误。 |
| `src/runtime/client/` | `session.ts` 管理文档、待保存变更和回执；`history.ts` 管理会话撤销；`autosave.ts` 协调 HTTP 保存。没有选中、弹窗导航或拖拽预览状态。 |
| `src/runtime/server/` | `batches.ts` 通过存储接口协调修订检查、幂等回执和批次提交，不直接使用 SQLite 或 Drizzle。 |
| `src/view/` | `graph-canvas.tsx` 提供独立画布；`default-editor.tsx` 接入默认范围和编辑动作；`node-shell.tsx` 提供节点外壳与控件交互隔离；`selection-details.tsx` 组合默认详情；`editor-store.ts` 管理选择、导航和拖拽预览；`scope.ts` 提供收录投影。 |
| `src/storage/` | `schema.ts` 声明数据库结构；`sqlite.ts` 实现一致读取、事务和 SQL 写入，在事务内调用核心结构校验。 |
| `src/ext/ai-video/` | 视频业务模型、独立表、图片上传、节点表单及 JSON 配置生成。 |
| `src/app/` | `frontend/main.tsx` 装配会话、画布和自动保存；`backend/index.ts` 装配存储、批次服务和 HTTP 路由。 |

`applyGraphChanges()` 返回图和完整结构变更，`applyDocumentChanges()` 补充范围布局和附加数据清理并返回文档及完整变更；编辑会话将同一份结果用于内存、保存和撤销，界面无需自行展开级联删除。坐标变化保留节点、边和挂载映射的引用。

图操作可以直接调用 `core`；不需要画布的编辑可以使用 `createSessionStore()`。界面通过 `createEditor(session)` 接入会话，并维护独立的画布状态。视频流程业务位于 `src/ext/ai-video/`，由应用入口装配；能力注册、节点激活执行和自动沿图运行尚未实现。

画布展示有两种组合方式：

- 使用 `App` 的 `renderNode`、`renderDetails`、`onOpenNode`、`nodeActions`、`onConnect` 属性，在默认收录编辑器中提供节点内容、附加详情和打开动作。未提供时仍显示 ID、基础详情，双击打开收录弹窗。渲染回调返回 React 组件，业务数据由调用方管理。
- 在 `ReactFlowProvider` 内直接使用 `GraphCanvas`，传入可见节点 ID、连线、逐节点坐标、选区和操作回调。画布不依赖收录结构、编辑会话或保存服务。坐标预览与拖动提交分别回调；选区回调使用函数更新，调用方基于最新选区应用它。

节点内的输入框、按钮、媒体控件和滚动内容放入 `NodeControls`。该区域使用 React Flow 的 `nodrag`、`nopan`、`nowheel` 边界，并隔离图快捷键、双击与右键；保留原生文字编辑、控件激活和内容滚动。其余节点区域保持拖动与选中。通用 `DetailsPanel` 只负责标题、内容容器和折叠；当前默认详情与调用方附加内容共享该容器。视频业务通过通用 attachment 变更另行接入持久化和撤销。主画布不订阅弹窗的选择和拖拽预览，弹窗标题只订阅成员和导航所需的数据。

- `migrations/`：Drizzle Kit 生成的结构迁移。
- `tests/`：真实 SQLite/Fastify 测试，以及通过 Axios 适配器验证保存队列。

```sh
npm test
npm run build
```

`npm run build` 包含前后端 TypeScript 检查。测试包含旧结构迁移、范围布局隔离、循环事务回滚、收录变更合并、跨范围删除撤销、直接成员展示与主画布选择恢复，以及短 ID 校验、核心独立操作、无画布会话保存与界面状态隔离。已确认开发范围见 `design.md` 的 1.3～1.7、1.9～1.12 节；其他产品目标留待逐轮确认。

## 视频流程编辑

顶部或右键菜单可新增图片、提示词和配置节点。图片支持 PNG/JPEG/WebP（最大 20 MB），上传后点击预览可放大。提示词直接在节点中输入，自动保存。

从图片或提示词节点右侧连到配置节点左侧，可连接多个输入、共用输入；配置节点中上下调整顺序，图片对应“图1、图2”，多个提示词换行合并。填写输出文件名和步数，点击配置节点标题，在右下角预览、复制或下载 JSON。导出等待保存成功，缺失输入或错误参数会显示具体原因。

业务定义与实现见 [src/ext/ai-video/README.md](src/ext/ai-video/README.md)。`0003_ai_video.sql` 新增 `ext_ai_video_nodes`，基础表没有业务字段。`runtime/attachments.ts` 提供通用业务数据挂载，复用现有保存与撤销；`storage/extensions.ts` 让业务表参与同一事务。

JSON 的图片路径相对于 `data/ext/ai-video/`；执行你自己的视频函数时，应把输入根目录指向该目录，或将图片和 JSON 一起带走。文件替换和节点删除保留原图片以支持撤销，本轮没有自动清理。只生成配置，不调用模型或同步 Google Drive。
